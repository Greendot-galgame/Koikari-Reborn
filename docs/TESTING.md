## UI 第一轮改进（2026-11-14，未递增发布版本）

- 标题页分为资源引导/可游玩状态，继续摘要使用与核心一致的兼容存档排序；阅读顶栏精简，增加隐藏/恢复界面。
- 隐藏仅在普通停页可用，先停止快进再检查资格；隐藏时仍绘制画面但不调用剧情 tick。第一次点击/空格/右方向键只恢复 UI，不提交剧情动作。错误、弹窗、切后台和显式导航恢复 UI，不自动重新隐藏。
- 新的对白组件与设置预览共享排版，支持不透明度、行距和可选页码；长文/说话人信息可滚动，操作按钮保持可达。大字号允许使用画面之外的留黑区域，不裁切场景。
- `scripts/check-native.sh --swift-only`：三 SDK Swift 6 严格类型检查、原有 19 条原生断言、219 条媒体策略断言、资源导入/路径测试及新增 184 条阅读策略/布局断言通过。**该选项明确不检查 Metal shader；默认命令仍执行完整检查。**
- `cargo fmt --check` 与默认 Rust 138 项测试通过；需要原作资源/GPU 的测试未启用。当前 Rust 1.95 的 Clippy 在未修改的 [coverage.rs](../src/coverage.rs) 上报告 `collapsible_match`，未将其当作通过或为 UI 修改抑制此 lint。
- 完整原生检查在 Metal shader 步骤因缺少独立 Metal Toolchain 中止。Release 构建在 Rust 过程宏加载阶段失败（`serde_derive` 的 `mis-aligned LINKEDIT string pool` / `foreign_types_macros` 无法加载）；Xcode 另报告本机 CoreDevice/CoreSimulator 组件版本不匹配。未修改系统工具链或绕过检查，因此没有可验收的新 Release 包。
- `bash scripts/render-ui-previews.sh` 将实际 SwiftUI 展示组件放入隔离的 macOS 离屏窗口，用合成数据生成标题、引导、设置和对白布局预览。夹具不初始化真实 Game、不读写用户偏好/资源/存档；macOS 窄窗口截图不是 iPhone 实测。
- 最终视觉按反馈收敛为系统按钮、原生分组表单与浅色对白框；移除了自绘字标、情书、爱心和星点装饰。标题只读使用原作 Logo 与淡化底图；没有将原作图片、脚本或个人资源路径放入源码。
- 原作 UI 接口仅接受两个固定标题路径；保留补丁覆盖、保护标志及校验失败拒绝，读入前限制解压后大小为 8 MiB，Swift 在解码前额外检查单帧、边长与像素数。重新运行默认 Rust 测试共 **145 项通过**（含新增 7 项 UI 资源边界测试）；三 SDK `--swift-only` 及原有策略回归通过，新增 **24 条 ImageIO/回退断言**使用合成图片通过。
- 私下只读检查了用户授权的 XP3；两个实际标题资源经新 `kr_ui_asset` 接口读出并与 Store 校验后的字节比较一致，读取前后标题状态快照不变，未执行剧情动作、播放音视频或读写原版存档。原作 UI 私有预览已在仓库外渲染，存档/对白仍为合成数据，不能当成实际游玩验收。
- 默认预览不读取原作图片。显式 `bash scripts/render-ui-previews.sh --artwork-directory PRIVATE_IMAGE_DIR --output PRIVATE_OUTPUT_DIR` 可用本地已校验的 `title-logo.webp`、`title-background.webp` 检查布局；该模式拒绝把输出放进仓库。两种模式均渲染 10 张 macOS 离屏夹具，显式设置激活窗口的控件外观，不代表窗口输入/焦点已验证。

- 最新首页精简：移除资源说明/状态页脚、存档摘要（含正文、页码与时间）及兼容状态入口；移除对应视图回调和摘要排序展示代码，但不改动自动存档、继续游戏或存档管理。首次资源导入与异常提示仍可用，正常首页只保留 Logo、操作和设置。三 SDK Swift 检查及原生回归通过，两种素材模式的 10 张离屏夹具已重新生成。
- **未验证**：完整原生 App 的真实游玩画面、真机、iOS 原生渲染、VoiceOver 与实际键盘焦点/长按连发、隐藏/恢复的端到端页码不变性、实际声音与全部媒体中断。策略断言和离屏布局均不能替代这些验收。

## 真实资源检查（必须自备）

资源只存放在仓库之外，运行前先备份用户存档；不要在公开 issue/CI 上传资源、存档或 QA checkpoint。

```sh
KOIKARI_ASSETS=/path/to/base KOIKARI_PATCH_ASSETS=/path/to/combined \
  cargo test --locked --release --test real_patch -- \
  --ignored --nocapture --test-threads=1

cargo run --locked --release --bin koikari -- \
  verify-targets /path/to/combined 5000000 --max-states 2000000
```

`verify-targets` 从首次到达各入口/选项的合法状态分叉，回放由自然终局进度调度。已有结果为 `targets_complete=true`、`complete=false`，零 direct probe、零未遍历目标或 blocker。`verify-all` 用于有预算的组合探索，预算耗尽必须报告失败，不能改写成完成。
